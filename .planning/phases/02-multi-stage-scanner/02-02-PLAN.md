# Phase 02, Plan 02: Sentiment Soft Input & Scanner-Oriented Worker Flow

**Status**: Executed
**Planned on**: 2026-05-07
**Goal**: Add a sentiment/news stage that returns agent-style soft input for shortlist candidates and complete the worker transition into a stage orchestrator for the scanner funnel.

## Context
- **Requirements**: `SCAN-01`, `SCAN-04`
- **Decision**: Sentiment is a `soft input`, not a hard gate.
- **Decision**: Sentiment output should look like an agent-style response with score/confidence plus reasons.
- **Decision**: `worker.py` should evolve into a stage orchestrator rather than one flat loop.
- **Decision**: Agentic/token-heavy reasoning should happen only after deterministic stages have narrowed the universe.
- **Decision**: Trade execution should consume enriched candidates and remain mostly deterministic.

## Proposed Changes

### 1. Sentiment Agent Contract

#### [NEW] `agentic_trader/agents/sentiment/agent.py`
- Add a dedicated sentiment/news agent that evaluates shortlist candidates.
- Return an agent-style result with:
  - signal or directional stance
  - confidence / score
  - human-readable reasons
- Keep the result shaped to plug into downstream discussion later, not to veto symbols directly.
- Run only on narrowed candidates to control token/API usage.

#### [NEW] `agentic_trader/services/sentiment/` or equivalent module path
- Introduce the minimal provider/service abstraction needed to fetch or derive sentiment inputs.
- Keep the implementation modest for Phase 2; the key objective is stage integration and output contract.
- Follow the existing `providers/` pattern so sentiment sources can be swapped or supplemented later.

### 2. Shortlist Enrichment

#### [MODIFY] `agentic_trader/worker/scan_state.py`
- Extend state to hold sentiment enrichment for shortlist candidates.
- Keep sentiment as auxiliary context layered onto the shortlist rather than replacing it.
- Attach sentiment to candidate context rather than storing it as an isolated vote list.

#### [MODIFY] `agentic_trader/worker/worker.py`
- Add a scanner-stage job that evaluates shortlist names with the sentiment agent.
- Ensure this stage runs after shortlist generation and before downstream discussion/execution.
- Keep the stage resilient to partial failures so one bad symbol does not collapse the entire enrichment run.

### 3. Worker Orchestration Cleanup

#### [MODIFY] `agentic_trader/worker/worker.py`
- Refactor the worker to make the staged scanner flow explicit and readable:
  - fundamentals universe stage
  - technical shortlist stage
  - sentiment enrichment stage
  - downstream trade discussion/execution stage
- Preserve the Phase 1 reliability guard rails while restructuring the flow.
- Keep provider calls and agentic calls budget-aware: broad stages should be cached/deterministic, narrowed stages may use richer reasoning.

#### [MODIFY] `agentic_trader/agents/discussion/agent.py` or integration call sites
- Prepare downstream discussion to accept sentiment as another soft vote/input source once present.
- Keep the weighting strategy simple for now unless explicit weighting changes are required by implementation.
- Treat discussion as final synthesis over enriched candidate context, not as the place where raw data fetching happens.
