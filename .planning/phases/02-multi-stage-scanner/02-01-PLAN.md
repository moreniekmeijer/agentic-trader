# Phase 02, Plan 01: Quality Universe & Long-Only Shortlist

**Status**: Executed
**Planned on**: 2026-05-07
**Goal**: Replace the current flat deterministic scanner with a staged fundamentals-to-technical funnel that builds a weekly `top 30` Quality Universe and a daily long-only `Active Shortlist` as enriched candidate context.

## Context
- **Requirements**: `SCAN-01`, `SCAN-02`, `SCAN-03`
- **Decision**: Source universe remains `S&P 500` only.
- **Decision**: Fundamentals stage outputs `top 30`.
- **Decision**: Technical stage is `long-only`.
- **Decision**: Providers/services produce facts; evaluators/agents produce judgment-shaped outputs.
- **Decision**: Scanner outputs should preserve enriched `CandidateContext`, not only symbols or votes.
- **Concern**: Current scanner scoring rewards both oversold and overbought names, which conflicts with a long-only shortlist.
- **Concern**: yfinance is an unofficial provider and must stay behind cache-friendly provider/service boundaries.

## Proposed Changes

### 1. Scanner Domain Model

#### [MODIFY] `agentic_trader/scanner/models.py`
- Extend scan result / scanner models so the system can represent:
  - `Quality Universe` outputs from fundamentals screening
  - `Active Shortlist` outputs from technical timing
- Add a `CandidateContext` or equivalent model that can carry:
  - symbol
  - stage scores
  - market/timing snapshot references
  - fundamentals context
  - evaluator/agent responses
  - freshness timestamps
- Keep these models focused on user-observable stage outputs rather than worker internals.

#### [MODIFY] `agentic_trader/worker/models.py`
- Add state structures for staged scanner outputs instead of a single flat shortlist.
- Preserve existing worker cache patterns where practical.

### 2. Fundamentals Stage

#### [MODIFY] `agentic_trader/agents/fundamental/agent.py`
- Reuse or extract fundamentals scoring behavior into evaluator-friendly pieces so it can rank the full S&P 500 universe consistently for scanner purposes.
- Make sure the output is usable for sorting into a `top 30` universe.
- Keep raw provider/service facts separate from judgment-shaped responses.

#### [MODIFY] `agentic_trader/services/fundamentals/fundamentals_engine.py`
- Support batch fundamentals screening over the S&P 500 source universe.
- Keep failure handling tolerant so individual symbol failures do not collapse the whole weekly stage.
- Preserve the existing provider abstraction so a future non-yfinance provider can be added without reshaping the scanner.

#### [NEW or MODIFY] `agentic_trader/scanner/engine.py`
- Introduce a fundamentals-stage method that produces the `top 30` Quality Universe from S&P 500 inputs.
- Stop using the current one-step `scan()` behavior as the only scanner entrypoint.

### 3. Technical Stage

#### [MODIFY] `agentic_trader/scanner/engine.py`
- Add a technical-stage method that only surfaces long-entry candidates from the Quality Universe.
- Correct the current buy/sell conflation so overbought names do not rank like long candidates.

#### [MODIFY] `agentic_trader/agents/technical/agent.py`
- Reuse or extract technical scoring into evaluator-friendly pieces to define what qualifies as a long-only shortlist candidate.
- Keep the shortlist behavior aligned with downstream discussion/execution expectations.
- Preserve timing context; do not reduce technical analysis to only `BUY`/`HOLD`/`SELL`.

### 4. Worker State & Cadence

#### [MODIFY] `agentic_trader/worker/scan_state.py`
- Persist and expose separate staged outputs in memory:
  - quality universe
  - active shortlist
- Keep access patterns thread-safe and worker-friendly.

#### [MODIFY] `agentic_trader/worker/worker.py`
- Split the current generic scan behavior into explicit scanner stages with distinct cadences:
  - weekly fundamentals refresh
  - daily technical shortlist refresh
- Keep downstream trade discussion/execution operating on the shortlist, not the full universe.
