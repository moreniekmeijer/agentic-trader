# Phase 03, Plan 02: Position Review And Bracket Leg Replacement

<objective>
Add a scheduled open-position review flow that evaluates current long positions, allows only conservative de-risking actions, and modifies Alpaca bracket legs through `replace_order_by_id` while recording each real order lifecycle event.
</objective>

<context>
- Depends on Plan 03-01 bracket entry order placement and active leg tracking.
- Phase decision D-04: exit management belongs in a separate open-position review flow.
- Phase decision D-09: agents may only de-risk.
- Phase decision D-10: raising take-profit targets or extending winners is deferred.
- Phase decision D-11: Alpaca remains source of truth before replacing bracket legs.
- Phase decision D-13: append events only when the system actually places, replaces, cancels, closes, or repairs bracket-related orders.
</context>

<must_haves>
<truth id="MH-01">The review job reads current Alpaca positions, not only current scanner shortlist symbols.</truth>
<truth id="MH-02">For long positions, a proposed stop-loss replacement must be greater than or equal to the current stored stop-loss price.</truth>
<truth id="MH-03">For long positions, a proposed take-profit replacement must be less than or equal to the current stored take-profit price when lowering the target.</truth>
<truth id="MH-04">Every successful replacement updates the active local leg ID from Alpaca's replacement response.</truth>
<truth id="MH-05">If Alpaca/local state disagrees, the job logs an event and skips blind replacement.</truth>
</must_haves>

<threat_model>
<threat severity="high">
Agentic review loosens a stop or otherwise increases downside risk.
Mitigation: validate proposed changes with de-risk-only guards before any Alpaca call.
</threat>
<threat severity="high">
Replacing a stale local order ID modifies the wrong or already-filled order.
Mitigation: fetch Alpaca order/position state before replacement and skip if the local active ID is missing, closed, or inconsistent.
</threat>
<threat severity="medium">
Replacement returns a new order ID but local DB keeps the old one.
Mitigation: update `Trade.take_profit_order_id` or `Trade.stop_loss_order_id` from the replacement response in the same transaction as the event record.
</threat>
<threat severity="medium">
Open positions without local bracket rows are silently ignored.
Mitigation: record a `repair_skipped` or `state_mismatch` event so missing protection is visible during verification.
</threat>
</threat_model>

<action>
Create `agentic_trader/worker/position_review.py` with:
- `ReviewAction = Literal["HOLD", "TIGHTEN_STOP", "LOWER_TAKE_PROFIT", "CLOSE"]`.
- `PositionReviewDecision(BaseModel)` fields `symbol`, `action`, `confidence`, `reasoning`, `new_stop_loss_price`, `new_take_profit_price`.
- `TechnicalExitReviewer` with constructor `__init__(self, multi_engine, technical_agent_factory=TechnicalAgent)`.
- function `validate_de_risk_only(trade, decision) -> tuple[bool, str | None]`.

`TechnicalExitReviewer.review(trade, position)` should fetch/compute current multi-timeframe market data for `trade.symbol`, generate a `TechnicalAgent` signal, and return:
- `HOLD` when the technical signal is `BUY` or `HOLD`.
- `LOWER_TAKE_PROFIT` when the technical signal is `SELL`, confidence is at least `0.3`, `trade.price` is present, and current price is above entry. Set `new_take_profit_price` to `round_alpaca_price(current_price)`.
- `TIGHTEN_STOP` when the technical signal is `SELL`, confidence is at least `0.3`, current price is not above entry, and current price is above the stored stop. Set `new_stop_loss_price` to `round_alpaca_price(max(trade.stop_loss_price, current_price * 0.98))`.
- `HOLD` with a reason if market data is incomplete or required trade fields are missing.

For long positions:
- `TIGHTEN_STOP` is valid only when `decision.new_stop_loss_price is not None` and `decision.new_stop_loss_price >= trade.stop_loss_price`.
- `LOWER_TAKE_PROFIT` is valid only when `decision.new_take_profit_price is not None` and `decision.new_take_profit_price <= trade.take_profit_price`.
- `CLOSE` is valid only when the trade has positive `qty`.
- `HOLD` is always valid and makes no Alpaca call.
If required current prices are missing on the trade, return `(False, "missing bracket price")`.
</action>

<action>
Implement `PositionReviewJob` in `agentic_trader/worker/position_review.py` with constructor `__init__(self, alpaca_controller, reviewer)`. `run()` should:
1. Log `Running position review job`.
2. Fetch Alpaca positions once with `self.alpaca.get_positions()`.
3. Query `TradeRepository.open_bracketed_trades()`.
4. For each trade, skip and record `state_mismatch` if the symbol is not present in Alpaca positions.
5. Produce a `PositionReviewDecision` using `reviewer.review(trade, position)`.
6. Validate with `validate_de_risk_only`.
7. For `TIGHTEN_STOP`, call `self.alpaca.replace_order(trade.stop_loss_order_id, stop_price=decision.new_stop_loss_price)`, update active stop ID and price from returned order, and record `stop_replaced`.
8. For `LOWER_TAKE_PROFIT`, call `self.alpaca.replace_order(trade.take_profit_order_id, limit_price=decision.new_take_profit_price)`, update active target ID and price from returned order, and record `take_profit_replaced`.
9. For `CLOSE`, call `available_qty = self.alpaca.get_available_qty(trade.symbol)`, then call `self.alpaca.sell(trade.symbol, min(trade.qty, available_qty))` only when available quantity is positive, and record `early_close_submitted`.

Tests can inject fake reviewers to verify each action without network calls.
</action>
