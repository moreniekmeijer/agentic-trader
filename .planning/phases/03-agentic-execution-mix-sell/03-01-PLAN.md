# Phase 03, Plan 01: Bracket Entry Orders And Leg Tracking

<objective>
Implement protected long-entry execution: every accepted BUY decision submits an Alpaca bracket order with deterministic stop-loss and take-profit levels, then persists the active Alpaca parent and leg identifiers needed for later management.
</objective>

<context>
- Phase decision D-01: execution is long-only.
- Phase decision D-02: `trade_job` should be a deterministic execution orchestrator.
- Phase decision D-03: entries remain market-style; Alpaca determines fill price.
- Phase decision D-05: every accepted BUY entry must include stop-loss and take-profit protection.
- Phase decision D-06: bracket levels should be volatility-aware with fixed-percentage fallback.
- Phase decision D-07: the default reward/risk target is roughly 2R.
- Phase decision D-08: stop is the hard floor and take-profit is the default ceiling.
- Phase decision D-12: persist minimal active operational IDs only.
- Phase decision D-14: model, mapper, repository, and API/read models must stay aligned.
</context>

<must_haves>
<truth id="MH-01">Every `BUY` order submitted by `DecisionEngine` uses Alpaca `OrderClass.BRACKET` and includes both `TakeProfitRequest` and `StopLossRequest`.</truth>
<truth id="MH-02">`SELL` remains close/reduce-only and never bypasses `get_available_qty()`.</truth>
<truth id="MH-03">`Trade.alpaca_order_id` remains the parent/entry order ID; active child leg IDs are stored separately.</truth>
<truth id="MH-04">The implementation does not add unused speculative persistence fields.</truth>
<truth id="MH-05">Existing Docker Postgres schema changes are addressed before worker runtime verification.</truth>
</must_haves>

<threat_model>
<threat severity="high">
Submitting a simple market BUY instead of a bracket BUY leaves an entry unprotected.
Mitigation: route BUY execution through `AlpacaController.buy_bracket()` and test the submitted request has `order_class == OrderClass.BRACKET`.
</threat>
<threat severity="high">
A SELL decision without a position opens a short position.
Mitigation: preserve `get_available_qty()` guard and add regression coverage for zero available quantity.
</threat>
<threat severity="medium">
Bracket prices are rejected by Alpaca because they violate sub-penny or stop-price constraints.
Mitigation: bracket policy rounds prices to 2 decimals for prices >= 1.00 and 4 decimals below 1.00; stop and target must straddle the reference price for buy brackets.
</threat>
<threat severity="medium">
New ORM fields exist in code but not in the running Postgres schema.
Mitigation: include an explicit schema alignment step and verify worker startup against the Docker database after applying it.
</threat>
</threat_model>

For long entries: `stop_loss_price = reference_price - risk_per_share`; `take_profit_price = reference_price + (risk_per_share * reward_risk)`. Round prices with helper `round_alpaca_price(value)` using 2 decimals for values >= 1.00 and 4 decimals for values < 1.00. Raise `ValueError` if no positive reference price exists.
</action>
